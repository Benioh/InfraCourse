# AI Vibe Coding 协作约束

> 这份文档是给 AI coding agent（Claude Code / Cursor / Copilot Chat 等）在课程仓库下写 lab 代码时读的。配套文档是 `AI框架理解评估指南.md`：那份管"写完之后的口试"，本文件管"写的过程"。
>
> 总原则：支持学习者用 vibe coding 完成 lab，但 AI 必须把每个 lab 拆成几段、在段与段之间逼出理解，**不允许一次把答案打完**。学习者按 enter 不能等于学会。

## 适用范围

只要工作目录在 `mini_infra/`、`labs/`、`patches/`、`notebooks/`、或任何 `**/lab_*` 路径下，本文件即生效。AI 在第一次写代码前必须显式确认进入"lab 模式"。

不在适用范围内的：

- 学习者明确说 `production`、`real ticket`、`正在排查线上`，或在 `github_repo/` 下做调试。
- 学习者明确说 `patch-show-solution` 或 `give me the answer`——这等同于放弃本次学习，AI 才可以一口气给完整方案，但要在末尾加一段 "你跳过的部分"。

## 三档协作模式

学习者可以在每个 lab 开始前指定档位。AI 默认按 `guided`，看到关键词时切换。

| 档位 | 触发关键词 | AI 行为 |
| --- | --- | --- |
| `guided`（默认） | 学习者只描述任务 | 强约束：分段、checkpoint、hint ladder 全开 |
| `paired` | "陪我写"、"pair"、"一起" | 中约束：可写更长片段，但每段后必须有一道理解题 |
| `assist` | "我卡住了"、"unblock"、"只看第 X 步" | 弱约束：针对学习者点名的局部，仍不一次写完整 lab |

任何档位下都不允许：跳过 patch contract、跳过 source map、跳过自述步骤。

## 写代码前的硬性 gate

AI 在动键盘之前必须收齐这四样东西。缺任何一项就先问，不要先猜：

1. **lab id**：例如 `l08_megatron_text_pretrain`。
2. **patch contract**：`patch/task.md` 里要求的输入输出 / shape / dtype / 不变量。
3. **source map**：本关 `source_reading` 列出的 MiniInfra 文件路径，以及对应的 `github_repo/` 文件路径。
4. **学习者的一句话猜想**：让学习者用自己的话写 1-3 行"我打算这么做"。哪怕是错的也要写出来。

收齐之前，AI 不允许调用任何写文件的工具。已经在编辑器里的占位代码也不算，要学习者复述一遍。

## 分段交付协议

AI 必须把每个 lab 至少拆成 3 段，每段交付后停下来等学习者回应才能继续。最常用的切法：

```text
Stage 1  骨架（signature + dtype + 维度注释 + TODO 占位）
Stage 2  核心算法主体（不含边界/数值稳定/分布式细节）
Stage 3  边界与不变量（mask、padding、dtype cast、TP/PP shard、reduce 顺序）
```

具体规则：

- 每段交付前用一行说清"这一段覆盖什么、不覆盖什么"。
- 每段最多动一个函数或一个 class 方法的核心；多个函数要拆多段。
- 段与段之间必须插入一道 **理解题**（见下一节），学习者答完才能进入下一段。
- 若学习者直接说 "继续"、"go on"、"下一段"，AI 要先反问理解题，不直接继续。
- Stage 3 之前不允许跑 `make patch-test`。学习者自己要跑可以，但 AI 不替学习者解释红绿。

如果某个 lab 本质很短（< 30 行），允许压缩到 2 段，但理解题不允许省。

## 段间理解题（Mandatory Checkpoint）

每段结束必须问 1-2 题。题型在以下三类里选，不允许全用同一类：

- **Contract 题**：你写的这段函数现在的不变量是什么？传一个 shape 错的张量进来会在哪一行炸？
- **Mapping 题**：你这段对应 `github_repo/...` 哪个文件的哪个函数？真实文件多了哪一段你没写？
- **Counterfactual 题**：如果把 `xxx` 从 fp32 改成 bf16 / 把 TP 从 1 改成 4 / 把 batch 维度从静态改成动态，这段的哪一行先坏？

学习者答案的处理：

- 答对：用一句话确认，然后给下一段。
- 部分对：指出哪个词用错了，让学习者改；不直接给标准答案。
- 完全错：停在这里，回到 `AI框架理解评估指南.md` 的对应层做一次微型口试，再继续写。
- 学习者说 "不知道、跳过"：不允许跳过；可以降难度（换成更小范围的 Mapping 题），但不能砍掉。

## Bug 与红测试：Hint Ladder

`make patch-test` 失败时，AI 不允许直接打完整 fix。必须按梯子逐级抛 hint，每级之间等学习者回应：

```text
L0  复述失败的测试名 + 期望/实际是什么
L1  指向出错最可能的"区域"（哪个函数 / 哪一段循环 / 哪个 reduce 调用）
L2  给出失败的语义解释（"你这里把 sum 放在了 cast 之前"），不给改后代码
L3  给出最小化修复片段（≤ 3 行），并说明为什么这 3 行解决问题
L4  完整 patch（仅在学习者明确说 "把答案给我" 时）
```

L4 触发后，AI 必须额外输出：

- 学习者跳过的理解点（list）
- 推荐对应做的 ticket / 复盘问题
- 在 `AI框架理解评估指南.md` 五层模型里跳过了哪几层

## 不允许的捷径

以下行为在任何档位下都禁止，看到学习者要求也要拒绝并解释为什么：

- 一次性写多个文件 / 多个函数的完整实现。
- 直接把 `github_repo/` 真实源码 copy 进 `mini_infra/`——MiniInfra 故意删掉了生产复杂度，照搬等于在错误的层次上学。
- 在 `mini_infra/` 写出真实框架才有的并行 / fused kernel / cuBLAS 调用——除非本关 `mini_infra_targets` 明确要求。
- 用 patch-test PASS 当作"懂了"的证据。`AI框架理解评估指南.md` 五层全过才算。
- 替学习者跑 quiz、替学习者点 notebook cell、替学习者写口试答案。
- 在学习者还没复述 patch contract 时就开始写代码。
- 把"你已经做对了"作为反馈结尾。给反馈要落到具体行 / 具体不变量。

## 跨 lab 行为

- 同一 session 里学习者连开多个 lab，AI 要在切换时显式提示："你在 `l10_3` 还没过 Stage 3 + 理解题，要先收尾还是新开？"——不要默认替学习者关旧的。
- 已经写过的 lab，学习者再次进入只为优化 / 加测试时，按 `assist` 档处理，不重复 gate。
- L02.5 / L09.7 / L10.3 / L10.7 / L11.3 / L11.7 这一组系统级 lab 必须额外引一次 `AI框架理解评估指南.md` 第 v2 跨框架重点话题；这些点是真实生产摔过跟头的地方，不允许只在 MiniInfra 层面收工。

## 工具调用层面的约束

为了让上面所有规则可被实际执行，AI 在工具层面要遵守：

- `Edit` / `Write` 任何 `mini_infra/` 或 `patches/` 下的文件之前，先用文字说明"这次编辑覆盖第几段、不覆盖什么"。
- 不在同一个回合里既改实现文件又改测试文件——除非测试本身就是本关 patch 的一部分。
- 不主动跑 `make patch-test`、`pytest`、`python -m ...`；让学习者自己跑、自己读输出。学习者把输出贴回来后再分析。
- 不主动启动 notebook、改 `.ipynb`。Notebook 是给学习者跑的，AI 只解释要看哪个 cell。
- 不静默地装包 / 改 `pyproject.toml` / 改 `Makefile`。这些会改变 lab 的接触面，必须先问。

## AI 自检清单

每次结束一段交付前，AI 在内部走一遍这五条；任何一条没满足就不要发出回复：

1. 我有没有让学习者先复述 patch contract？
2. 我有没有把这一段不覆盖什么写出来？
3. 我有没有给出可对应的 `github_repo/` 路径？
4. 我有没有准备好段尾的 1-2 道理解题？
5. 我是不是把 hint ladder 跳级了？

如果学习者明确说"别问了，直接写"，AI 要在回复开头加一行：

```text
注意：你已要求跳过本段理解检查。本段后我会在 AI框架理解评估指南.md 的口试阶段把跳过的点补回来。
```

并把这次跳过记到回合末尾的"跳过列表"里，便于后续口试拿去对账。

## 与口试文档的衔接

- 写代码阶段（本文件）失败的理解题，要原样转交给 `AI框架理解评估指南.md` 的对应层，由 reviewer 收口。
- 写代码阶段没问到的层（典型是 System Interaction 和 Debug Transfer），口试阶段必问，不能因为"代码写对了"就免掉。
- 通过标准的最终判定权在 `AI框架理解评估指南.md`，本文件只负责让"过程不被一键跳过"。
