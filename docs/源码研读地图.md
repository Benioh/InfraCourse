# 源码研读地图

下面的路径是每关 README 和 Web UI `source_reading` 的汇总，用于 code reading 课前准备。

## MiniInfraLM 主线源码地图

MiniInfra 的阅读顺序是“先最小同构骨架，再真实源码”。不要把它当成孤立练习脚本；它的目录和生命周期对应 `github_repo/` 中的真实项目。

- `mini_infra/megatron/pretrain_gpt.py`、`training/training.py`、`training/checkpointing.py`：对照 Megatron `pretrain_gpt.py`、training loop 和 distributed checkpoint。
- `mini_infra/megatron/core/tensor_parallel/layers.py`、`core/pipeline_parallel/schedules.py`、`core/optimizer/distrib_optimizer.py`：对照 Megatron TP/PP/distributed optimizer 的核心不变量。
- `mini_infra/vllm/entrypoints/openai/api_server.py`、`v1/engine/llm_engine.py`、`v1/core/sched/scheduler.py`、`v1/core/kv_cache_manager.py`：对照 vLLM OpenAI entrypoint、engine、scheduler 和 KV block manager。
- `mini_infra/sglang/srt/managers/scheduler.py`、`srt/mem_cache/radix_cache.py`、`srt/managers/disagg_service.py`：对照 SGLang scheduler、radix prefix cache 和 PD disaggregation。
- `mini_infra/slime/train.py`、`slime/ray/rollout.py`、`slime/ray/train_actor.py`：对照 SLiME train loop、RolloutManager/RolloutServer 和 TrainRayActor。
- `mini_infra/source_alignment.yaml`：每个 MiniInfra 文件到真实项目文件的机器可读映射。

每关读真实框架源码前，先读对应 MiniInfra 同构最小实现，明确保留的不变量和删掉的生产复杂度。

每关 source_reading 的默认顺序是：MiniInfra 主线文件 → `github_repo/` 真实源码 → lab 脚本/配置 → notebook 解释。旧 toy 文件可以辅助理解，但不能作为报告主证据。
